## 结论

**此次摘要变化仅来自画布视图和原生 Agent 节点的刷新时间戳。实际配置、组件代码、节点布局及连线没有变化，发布版本与运行工件没有变化。**

这次结论来自截图前后完整草稿的逐字段比较，不再仅依据操作记录或整体摘要推断。

| 对象 | 截图前后全部变化 | 未变化的内容 |
|---|---|---|
| 合同附件＋企业制度＋技能计算，6节点/5连线 | `Agent-EXpSZ` 的 `data.node.last_updated`；`viewport.x`、`viewport.y`、`viewport.zoom` | 所有节点模板与字段值、提示词、资源ID、技能脚本开关、组件代码、节点位置、输出选择和连线 |

`viewport` 是编辑画布的平移和缩放，不是节点布局或业务参数。`last_updated` 是前端动态模板刷新的时间戳，不表示组件代码发生修改。仅去掉这两类字段后，截图前、截图后、当前库内草稿以及日志覆盖区间内的中间已提交版本全部一致。

## 为什么没有手改参数也会保存

安装中的 Langflow 前端存在以下链路：

1. 字段挂载初始化会检查动态刷新条件。两个发生时间戳变化的都是原生 Agent 节点；它们的 `model` 字段启用了动态刷新，并具有空的 `api_key` 字段，满足初始化刷新条件。模型仍来自已连接的 TeKnowra 模型节点，本轮没有填入供应商密钥。
2. 前端发送模板刷新请求时生成 `new Date().toISOString()`，收到结果后把这个值写入节点 `last_updated`。即使返回的模板、输入值和输出定义完全相同，时间戳也会更新。
3. 前端通过 `setNode` 更新节点后调用 `autoSaveFlow`。
4. 保存流程时使用当前 nodes、edges 和 `reactFlowInstance.getViewport()`，把整个图对象写入草稿，因此当前平移/缩放也进入保存数据。
5. 上次整体摘要包含时间戳、节点元数据和视图，必然因此变化；整体摘要变化不能直接解释为业务配置变化。

上述链路定位于当前安装包的 `langflow/frontend/assets/index-CumK2M5X.js`：字段挂载刷新函数 `bmo`、模板刷新函数 `zF`、动态模板合并函数 `__`、流程状态 `setNode` 与保存回调。该文件是压缩构建产物，具体字符偏移记录在配套 JSON，不能把偏移当源码行号。

本轮没有修改这一行为。这里只确认本次变化的性质，不据此保证未来所有自动保存都只影响视图；后续改参数或更新组件仍应按草稿、发布、验收流程处理。

这里检查的是日志中保留的已提交版本，不声称观察了未保存的浏览器临时状态。
