# Eino 业务定义统一接入

目标：新增业务场景不再修改配置解析器、聊天入口或通用运行调度。用户已授权继续下一步；在当前工作区实施，保留已有修改，不提交、不上线。

## 决策

采用编译期发布目录与能力描述。继续硬编码各场景的分支会重复集成工作；动态加载不受审代码会扩大运行边界，当前没有必要。定义仍是研发维护的代码，发布仍需要编译和服务器配置绑定，不承诺拖拽发布或热加载。

目录描述定义 ID、显示名称、所需知识或按人 OAuth 只读工具；本轮支持两个互斥能力档位，暂不开放混合档位、写操作、记忆、图片、多轮。通用服务根据能力档位装配现有权限回调。运行时目录保存图构建函数和可选输出前业务复核；身份、知识引用复核、预算、事件和完成状态仍由通用执行器负责。

现有合同审查与信用查询行为保留。信用的客户访问复核由其业务定义声明，通用执行器不再比较信用定义名。默认旧引擎、旧合同 Agent 保护、精确 Agent ID 绑定、未知定义拒绝保持不变。

新增 knowledge-summary-v1 作为第三个接入样例：授权检索、受证据约束摘要、引用复核。它只证明新模块的接入，不冒充先前尚未发布的自主多 Agent 原型。

## 验收

1. 三个已发布定义均能解析绑定，未知/重复/非法配置仍拒绝。
2. 每个目录定义都有运行构建器；业务专用名字仅出现在目录、业务实现及兼容测试辅助中。
3. 第三个定义通过真实通用 Engine.Execute 路径，产生引用和完成事件；输出前权限变化不产生答案或完成事件。
4. 原合同、信用、OAuth 等针对性测试通过；后端编译成功。

本轮不修改 UI、不改本机 Agent 绑定、不重启服务、不上线。浏览器正式发布验收与 ADK 模板产品化是后续工作，不能以单元测试替代。
