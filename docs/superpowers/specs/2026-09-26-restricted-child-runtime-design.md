## 目的与证据

用户需要可持续维护、开源可定制的企业 AI 基础设施，尽量复用 TeKnowra 的企业能力与外部框架的编排能力。当前候选为 Eino 编排原生 Agent；本稿只设计其必要的受限子任务入口，不代表最终平台选型已不可撤回。

本稿不恢复 2026-09-24 已撤回的“先整理整个执行边界”建议。必要性来自 2026-09-26 实测：

- 通用工厂在 AllowedTools 仅含知识读取且 Skills 关闭时，仍注册并执行沙箱写文件；SharedAgentReadOnly 不能阻止。
- 文档级 SearchTargets 限定 A 时，同库 B 标题仍进入模型输入，虽然工具拒绝读取 B。

证据：`D:/TeKnowra/research/Eino子任务工厂边界实测-2026-09-26.md`；可运行探针 `D:/TeKnowra/research/eino-native-probe/factory_probe_test.go`。

## 方案选择

| 方案 | 收益 | 成本或缺陷 | 决定 |
|---|---|---|---|
| 修改配置后直接调用通用工厂 | 接线少 | 实测不能保证只读和输入范围 | 不采用 |
| 为通用工厂增加贯穿所有能力的全局策略 | 长期统一性较好 | 牵动普通 Agent、技能安装、MCP、网页与沙箱；当前验证不需要全部能力 | 暂缓 |
| 新增受限运行入口，复用原生工具和执行循环 | 不触发通用工厂的独立能力注册；影响面较小 | 需维护少量工具装配与限定元数据逻辑 | **首版采用** |

第三种方案不是另写 Agent 循环或权限系统。复用原生 NewAgentEngine、知识工具、资源授权及模型适配，新增的是封闭能力入口。首版仅有三个知识工具构造调用，不为此重构通用工厂的完整 switch。

## 首版范围

实现并验证受限运行入口，不接产品 HTTP 路由，不新增数据库表、前端入口或 Eino 产品依赖。其后才接 Eino 的父会话执行分支。

第一种任务为“对明确选择的文档做带来源摘要”。输入为服务端任务类型与文档选择，不直接接收主模型生成的任意提示词、历史或资料正文。首版重点验证普通文档库中的明确文档范围；FAQ、未解析为文档集合的标签范围、整库任意规划等返回明确的不支持错误，不降级成更宽范围。

只允许以下候选工具，实际集合仍与父运行已允许的知识工具相交：

- `knowledge_search`：只有父运行具备该能力、模型与重排依赖已准备且文档范围有效时才可启用。
- `get_document_info`。
- `list_knowledge_chunks`。

首个确定性验证场景可只启用后两者；开放 knowledge_search 后需另做真实检索后端验收，不能以文档分块读取代替。

不提供沙箱、文件、shell、网页、MCP、Wiki 写操作、定时任务、长期记忆和动态工具发现。它们是后续独立能力，不以占位实现声称支持。

## 接口契约

下面为拟议形状，不是已有 API，也不是可直接粘贴编译的补丁。类型先留在 application/service 包内部，避免把尚未稳定的协议扩散到所有 AgentService 调用方。

```go
type restrictedChild interface {
    Run(ctx context.Context, req childTaskRequest) (childTaskResult, error)
}

type childTaskRequest struct {
    kind        childTaskKind // 首版仅 summarize_documents
    documentIDs []string      // 候选 ID，必须重新验证为父范围子集
}

// 由可信 service 准备，不接受 HTTP JSON 直接反序列化。
type preparedChildParent struct {
    // 私有：Caller、Principal、父 session/message ID、授权 SearchTargets、
    // 父级知识工具集合、已经解析的模型、模型窗口及明确的执行预算。
}

func (s *agentService) newRestrictedChild(
    parent preparedChildParent,
) (restrictedChild, error)
```

`Run` 每次构造自己的配置、Registry、EventBus 和原生 Engine。它不返回原生 Engine，不暴露 SetMemoryPrompt、SetSteerSink、任意 llmContext 或图片参数。准备数据深拷贝；运行记录不保存在可并发复用的共享字段中。

`preparedChildParent` 的来源只能是已经走完真实会话/Agent 访问授权与 buildAgentConfig 的服务端链路。私有类型仅减少误用，不是针对进程内恶意代码的安全隔离。首版测试可用包内夹具创建它；这不等于产品接线已经完成。

## 身份与范围

1. 要求 Run 的 context 包含有效 Caller 和 Principal，并与创建入口时捕获的父身份一致；缺失或不匹配直接拒绝。执行租户与原始调用者分别保留，不从前者推导授权。
2. 文档 ID 通过现有授权读取服务解析。验证数据库返回的真实 KB/租户与父 SearchTargets 匹配；父级为文档范围时必须在其 KnowledgeIDs 内。
3. 先验证调用者当前可读，再验证任务范围子集。这是两项不同条件：用户能访问某文档，不代表这次子任务选中了它。
4. 复用既有权限内核处理共享资源；首版不复制一套共享/角色规则。仍有未验证语义的共享 Agent grant 场景应明确拒绝或暂不进入首版接入渠道，不做默许。
5. 已解析文档标签目标保留其全部约束；不能只比较 KB ID 后丢掉 TagIDs、ScopeTagIDs。首版遇到不能无歧义收敛的范围返回不支持。
6. 全部所选文档必须通过，才创建模型调用；任何未知、失效或超范围 ID 都使任务失败。空选择也失败，不回退到整库。
7. 输入切片、map 和每个 SearchTarget 独立复制。不得借 ValidateConfig 或并发执行修改父配置与兄弟任务范围。

本阶段保证运行开始时的核验和本次不可扩大的范围，不宣称运行中权限撤销会即时生效。现有 context grant 可能继续有效；要支持即时撤权，需专门设计重新查权/版本失效机制，不能只重复调用命中旧 grant 的检查。

## 工具约束

受限入口不调用通用 CreateAgentEngine 或 registerTools，也不调用任何沙箱/MCP/网页注册方法。三个知识工具复用原有构造函数和服务依赖。

为防未来新增注册路径意外扩大能力，在 ToolRegistry 增加可选的不可变允许集合：

- 新增 `NewRestrictedToolRegistry(allowed []string)`；现有 NewToolRegistry 维持原行为。
- 受限模式空集合表示没有工具；通用模式的 nil/默认含义不得混淆。
- RegisterTool 与 RegisterDeferredTool 均不能保留名单外工具。保持现有公开方法签名，拒绝行为可记录诊断；受限工厂在创建后核对实际工具集合与预期一致，否则返回错误。
- GetTool、模型定义投影与实际执行路径遵守同一集合；在内部统一 execute 方法再次检查真实工具名，防止通过其他调用入口绕过。
- 没有运行期扩大名单的 setter。拒绝名单外调用必须发生在工具 Execute 之前，测试用副作用计数器证明。
- 首版不注册任何 MCP 代理或目录。将来启用代理时，必须按实际目标能力授权；单独允许代理名称不够。本次 Registry 名单机制不宣称已经解决未来 MCP 的授权问题。

服务层只接受三个已知候选名称；未知能力或依赖缺失直接失败，不能悄悄退回默认工具。即使最终集合为空，Registry 仍必须保持空；对于需要读资料的摘要任务，服务层应在模型调用前报“无可用知识读取能力”。

## 模型输入与结果

不复用通用 getKnowledgeBaseInfos 的“最近文档”查询。仅按已验证的文档 ID 构造 SelectedDocumentInfo，首版不注入整库概览、整库 doc_count 或其他文档标题。知识库自由文本描述也可能含范围外信息，因此不默认附加。

子模型输入由固定摘要任务模板、获准文档元数据和获准工具结果构成；历史为 nil，不注入父记忆、附件、图片、兄弟结果、父自定义系统提示词或父会话全文。服务器固定任务模板取代不受限制的主模型自由文本任务说明。

后续若支持自定义问题或主 Agent 动态任务说明，必须明确该文本可携带哪些资料及由谁审查。仅检查 ID 无法保证父模型不会在自由文本中复述其他资料。也不承诺对获准文档内部已有内容进行语义保密识别。

回执应包含：任务 ID、状态（success/failed/cancelled）、答案、来源、工具执行摘要和用量。来源来自真实工具结构化结果，不信任模型自行填写的来源 ID。失败/取消回执不得伪装成成功；首版可采用保守规则：任一知识工具失败，任务标为 failed，并保留已完成步骤供父级诊断。

只用 AgentState.KnowledgeRefs 不足以满足现有探针观察到的引用行为；需在知识工具结果边界记录受限来源，并在汇总时按已授权文档校验。引用映射由父级重新分配，子任务 c1 等局部 ID 不直接入库。

每次运行从父 context 派生有界 context，不用 logger.CloneContext 脱离父取消。执行预算必须正数且不超过父分配值；不接受 UnlimitedMaxIterations。并行任务的总额度由后续父编排器预分配，不能把每个子任务上限误称为全局硬预算。真实提供商的 token 统计仍以已有适配为准。

## 会话生命周期

受限子任务只返回回执，不创建父消息、不设置 LiveRun、不持久化第二套会话记录，也不使用父 SteerSink。子任务有独立 EventBus；错误与完成事件不直接透传父 bus。

后续接 Eino 时由父适配器统一：取消、用户追加消息策略、引用转换、用量合计、失败策略和唯一整轮 complete。用户可见状态应分清“结束”和“业务成功”。这一阶段不承诺崩溃恢复或审批挂起恢复。

## 验收矩阵

| 类别 | 必须证明 |
|---|---|
| 合法读 | A 的元数据/分块可读，真实工具正常执行，来源能映射到持久 ID |
| 写入隔离 | 后端声明文件系统能力，父配置包含沙箱且 Skills 开启时，受限子任务仍无写文件、编辑、shell；伪造调用不产生副作用 |
| 其他能力 | 父配置有 MCP、网页、记忆或定时任务能力，受限构造不初始化/注册这些能力 |
| 输入隔离 | A 与 B 在同库，仅允许 A；首次和后续全部模型输入均无 B 标题、描述或夹具正文；父历史/附件/记忆标记不被复制 |
| 范围错误 | 未知 ID、同库 B、其他租户文档、空选择、缺失权限、无法收敛的标签范围在调用模型前失败 |
| 身份 | 错误 Caller/Principal 不能使用已准备入口；执行租户变化不改变授权调用者 |
| Registry | 受限空集不回退；延迟注册也不能扩大；伪造与内部执行均拒绝；普通工厂既有行为保持 |
| 并发 | 两个任务不共享可变配置、工具、来源映射；原父范围不变；每个回执归属正确 |
| 停止与错误 | 父取消到达两个已开始任务；工具失败不当成功；不产生父完成事件或持久化副作用 |
| 普通路径 | 现有 Agent 工厂、沙箱文件、技能安装和 Registry 测试继续通过 |

此前 factory_probe_test 是“复现旧行为”的研究测试，应保留其含义，不把断言偷偷改成通过新契约。新受限入口用独立测试证明上述要求，普通工厂继续保留原行为时旧复现仍可能成立。

验证分层：先确定性单元/集成夹具；再复用隔离 PostgreSQL/Redis 验证身份与来源；接产品入口后才做浏览器验收。涉及 knowledge_search 时另行准备真实检索后端。未到该阶段不能用上一轮证据替代。

## 风险与实施准入

主要风险是共享 Registry 的兼容性、权限快照与任务范围交集、模型输入间接泄露、来源与失败语义。能力名单本身不能约束获准知识工具内部调用的外部服务；首版仍依赖既有知识服务和所配置模型提供商的部署信任边界。

本设计可以作为后续实施计划的输入。先完成受限入口验收，再引入 Eino，避免把工厂约束、编排效果和页面接线问题混为同一故障。即使入口通过，也不等于企业 Agent 基础设施已经完整。

本阶段尚无产品实现、修复验证或工期实测；已有研究证据只支持上述局部约束的必要性。
