# Langflow 成组运行与版本包设计

用户已授权按“确定拓扑→固化可安装/回滚版本包→隔离环境验证”连续实施；不部署生产，保留全部未提交修改和已有验收数据。

## 首版边界与选择

研发在 Langflow 编辑私有草稿，TeKnowra 负责身份、知识、模型、MCP OAuth、技能和发布。首版单实例，已有文本、多 Agent 委派、共享语义保持。这里不扩展长期任务续跑、并行桥、SSO或高可用。

工程选择（实施者判断）：正式容器拓扑采用两个进程/容器共享一个网络命名空间。TeKnowra 和 Langflow 通过127.0.0.1互调，动态能力端口只在该命名空间内；不把能力桥暴露到宿主或公网，不简单删除现有loopback保护。Langflow不挂载平台env、OAuth存储或Docker socket。编辑/运行身份仍分离；研发UI经过绑定宿主回环的入口，远程入口及证书由部署方网关管理。服务从同一个不可变版本清单取组件、运行依赖和平台版本。

另一方案是独立网络服务+固定认证网关，会新增能力路由、网络身份和攻击面；本轮不选。Windows原生同机双进程共享回环具有同等协议拓扑，可用于低资源的真实Langflow隔离验证，但不能冒充完整Linux容器安装已验收。

## 版本包

新目录 integrations/langflow/delivery：标准库Python发布工具、启动器、Compose模板和README。版本包只包含明确白名单的组件/support、启动器、运行依赖锁及指纹、清单；绝不扫描/打包.env、数据、图、凭据、日志或现有Python环境。平台/运行镜像引用使用不可变digest；未提供镜像时只能生成明确标记的native验证包，禁止冒充容器交付包。

包manifest记录格式版本、release ID、目标平台、平台工件SHA、Langflow版本/依赖与关键源码SHA、每个成员SHA。安装解包先验证路径、大小、成员集合、SHA、symlink/目录逃逸，安装至独立根/releases/<ID>。版本目录不覆盖；current.json原子切换，坏包/坏运行环境不改变活跃指针。回滚切回完整旧包，不回滚数据库schema或静默降级依赖；先核对原运行依赖，若不符拒绝并要求恢复匹配环境。活动服务切换须停旧进程后启动，工具不操作未知PID、不自动迁移数据库。

平台工件可以是当前Windows构建二进制（native验证），或待构建的不可变平台镜像（container包）。不把当前有大量未提交修改的HEAD SHA当作已构建镜像。正式Linux平台镜像缺失时必须明确列阻塞项，不能用旧本机镜像顶替。

## 隔离测试

所有测试在 D:/TeKnowra/research/selection/langflow-delivery-test-20261015，自有端口17861/独立安装根、SQLite、身份和日志；不使用既有7861数据，不复制当前服务密钥、不调用真实CRM或生产。真实LF测试使用合成模型回环服务，不消耗企业模型余额；验证关闭匿名/auto_login、编辑/运行私有隔离、宿主组件经过每任务能力回调、版本安装/升级/回退、篡改拒绝、重启后固定版本保留。

现有受信Python安装可作为验证先决条件复用，但必须用版本/关键源码SHA验证，实际运行从新安装的组件包取代码。测试报告区分“原生真实运行”“Docker共享网络探针”“完整容器栈”，没有跑到的层级不标通过。本机RAM约0.4GB，先检查资源，只暂停本任务的旧LF/后端进程并记录恢复入口，不停其他系统、不清Docker、不删业务卷。完成后恢复旧验收进程。

## 验收

1. 新安装根可安装两版本、切换、回退；拒绝篡改、未知成员、路径逃逸和不兼容依赖，不动当前版本。
2. 包内无密钥、运行数据及临时能力；当前环境和已有未提交修改不被覆盖。
3. 隔离真实LF通过认证、私有Flow、受控模型组件调用和安装版本切换，日志不导出凭据。
4. 共享网络拓扑以本机受限Docker探针或完整栈核验，明确证据层级；资源/镜像不可用时保留包与诊断，不宣称生产可交付。
5. 最后一次fresh只读代码审查，重要项一次TDD修补；不提交、不推送、不上线。
