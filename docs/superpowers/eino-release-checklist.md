# Eino 交付与发布清单

核验日期：2026-10-11。本清单固化已有四种定义和本机验证，不宣布生产就绪或自动授权上线。

## 当前能力

|定义|模式|平台能力|本机状态|
|---|---|---|---|
|contract-review-v1|固定知识审查工作流|授权知识、引用、事实复核|正式聊天通过|
|knowledge-summary-v1|固定知识摘要工作流|授权知识、引用、事实复核|正式聊天通过|
|customer-credit-readonly-v1|固定只读工具工作流|单服务本人 OAuth、访问复核|正式聊天通过|
|business-review-multiagent-v1|主 Agent 自主选择固定专家，顺序委派|授权知识 + 单服务本人 OAuth、专家归属、统一预算|单/双专家及授权恢复通过|

当前只读、文本、单次任务、工作区内独立 Agent；不支持写业务、多轮、图片、技能、长期记忆、并行/动态专家和进程重启后续跑。IDE 可生成编排代码，但 TeKnowra 资源目录选择器未实现。专家为研发发布的代码模块，不是任意界面 Agent 组合。

## 交付记录（每个新业务填写）

- 业务目标、使用者、明确的可做/不可做操作。
- 定义 ID/版本、代码文件、模型依赖、知识范围、MCP 服务和固定工具、专家职责。
- 合成验收样本、期望事实/结论、拒绝或缺失信息场景；业务质量与底座执行结果分开记录。
- 实际开发工时、业务文件变化、底座文件变化及原因。不凭模板复用推算成本降低百分比。
- 自动测试输出、浏览器会话/run_id、来源引用、错误与取消表现。
- 构建提交/镜像、配置注入方式、回退版本、试点负责人和用户反馈。

## 本机交付检查

1. 能力在既有档位内：新增业务模块和两份发布清单即可，配置解析器/聊天入口/OAuth 不应跟着业务名称改。需要新档位时单独评估与验收。
2. 工具在发布清单内且业务语义确实只读；MCP 按人 OAuth，不使用共享服务账号兜底；客户雪花 ID 保留字符串。
3. 所需模型/重排模型在目标空间可用；资源授权由运行使用者决定，不能把研发可见资源直接当成企业用户权限。
4. 固定知识档位仅 search_knowledge；工具档位为单服务、工具精确集合；混合档位两者合并。禁用当前不支持的附加能力。
5. 代码测试、编译、正式浏览器聊天验收有证据。未使用知识不能制造引用；部分失败不能发出成功完成。
6. 环境绑定合并，保留旧 Agent；旧合同 Agent 854499ab-7e55-4be0-a681-807a096fea4e 受保护不能重绑。未绑定 Agent 仍走原引擎。

## 生产试点前待执行

1. 选择小范围业务用户并完成业务质量样本评审，确定故障联系人和回退条件。
2. 整理当前未提交改动：区分既有改动与本次改动，确认一起发布的范围；不把本机 .env、凭据、日志、备份纳入提交。本清单不替用户提交或上线。
3. 服务端生产绑定使用生产 Agent/知识/MCP ID，不能复制本机 ID 当成生产配置。区分 env_file 注入和文件挂载；env_file 值变化需正确重建，仅重启无法重新注入。
4. CI 产出不可变提交镜像；服务器不构建镜像。遵守根目录接管与上线手册的 TeKnowra-VerifiedRelease 流程，禁止恢复旧常驻 watchtower。
5. 更新后比对运行容器镜像 ID 与目标提交镜像，核验前后端版本和代理健康。经公网浏览器实测登录、业务聊天、引用、授权卡及同任务恢复；不能以 API 200 或 GitHub 构建成功代替上线验收。
6. 失败按已核验回退版本恢复代码/绑定，不删除数据库、OAuth 持久卷，不做全局 Docker 清理，也不操作其他项目。

## 当前遗留

答案语义仍受模型影响，需要业务评测；独立模型复核不是正确性保证。上一轮聊天有图片占位显示异常，未修复，生产试点前应确认实际影响。既往全量 service 测试存在失败且尚未做基线比对，本轮针对性通过不等于全仓通过。重启后任务恢复尚未实现，应在试点运维中明确。
